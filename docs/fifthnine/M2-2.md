# M2-2: Spring Boot application configuration extraction

Status: IN REVIEW. Not merged. Branch `feature/m2-2-spring-config`. Plan: `M2_PLAN.md`. Scans still report `INCOMPLETE`, there are no rules, and nothing reaches the network.

## What was delivered

- **Config readers** (`extract/spring_config.py`, `extract/properties.py`): `application.{yml,yaml,properties}` and profile variants, multi-document YAML and `#---` properties documents, YAML 1.1 scalars as SnakeYAML reads them (`off` is a boolean, `0755` is octal), aliases refused, entry and nesting caps, line numbers on every entry.
- **Resolver** (`resolve/spring.py`, `resolve/springprops.py`): production-effective values with Spring Boot's precedence, low to high: config files, OS environment (Dockerfile `ENV` below container `env`), system properties (`JAVA_TOOL_OPTIONS`, `JDK_JAVA_OPTIONS`), `SPRING_APPLICATION_JSON`, command-line `--k=v`. File order follows location, extension and profile rules; profile includes and groups expand as Boot expands them. Placeholders `${name:default}` resolve against the same sources.
- **Overridden facts.** Every shadowed value is emitted with the origin that lost, so a reviewer can see what was set and what won.
- **Exposure.** An `envFrom` Secret or ConfigMap that is not in the repository gives `env_possible` and names the source and the variables that could carry the key. A config directory mounted at the working directory, `SPRING_CONFIG_LOCATION`, `SPRING_CONFIG_ADDITIONAL_LOCATION`, `SPRING_CONFIG_IMPORT`, `spring.config.import` and the `spring-cloud-kubernetes` config dependency give `file_possible`. Derived facts are `inherited` and cite their inputs.
- **Actuator endpoints** derived from the effective properties: management port type (same, different, disabled), base path, path mapping, probe groups, `add-additional-paths`, exposure and access (`access` on Boot 3.4 and later, `enabled` on 3.3 and earlier). The result is a concrete path and port per health endpoint, or an absent endpoint.
- **Defaults table** `data/defaults/spring-boot.v1.yaml` for Boot 3.2 to 3.5. Each default cites the upstream line; `verified_at` is empty until the upstream anchors are extended in `verify_upstream.py`.
- **Redaction.** Values of secret-named keys, URL user info and `password=` style query values become `<redacted>` before they reach any fact.
- **Deployment link.** `DeploymentResult` now carries container links and args so the resolver reads the command line and environment of the container that runs the module.

**Independent oracle.** `tests/support/spring_oracle.py` does not import the resolver. It reads YAML with PyYAML's composer and SafeConstructor, `.properties` with `javaproperties`, and Dockerfile `ENV` with the BuildKit parser, then recomputes layering, profile expansion, placeholders, container env and args, and endpoint paths. It is a second implementation of the same written rules by the same author, so it catches slips and not a shared misreading of Spring. That is why a runtime fixture job (below) remains open.

**Carried forward from M2-1.** The 1,778 oracle skips disclosed in M2-1 remain coverage limitations. They are not counted as verified here or there.

## Known limits

- Defaults are assumed stable across patch releases inside a minor version. Boot outside 3.2 to 3.5 gets no defaults and unresolved derived facts.
- The contents of a ConfigMap-mounted `application.yml` are not parsed; the mount is reported as exposure only.
- Exposure variables cover the relaxed name, `SPRING_APPLICATION_JSON`, `JAVA_TOOL_OPTIONS` and `JDK_JAVA_OPTIONS`. Other injection routes (init containers, entrypoint scripts) are not modelled.
- `setAdditionalProfiles` in code waits for M2-4. `spring.config.activate.on-cloud-platform` documents are skipped with a notice.
- A second container for one module gets subjects suffixed `@container`; the oracle does not cover those.
- There is no runtime oracle, because the build environment cannot reach Maven Central.

## Review

Round 1 was done by a separate agent instance that had not seen the implementation or the oracle. It is the same model family as the author, so it is independent of the author's reasoning, not of the model. It reproduced each finding on a small repository. It fetched Spring Boot 3.4.13 sources for four of them.

| # | Severity | Finding | Disposition |
|---|---|---|---|
| 1 | major | `application-default.*` never loaded when no profile is active | Fixed; test `test_default_profile_file_is_read_when_no_profile_is_active` |
| 2 | major | `-D` after `-jar` read as a system property | Fixed: `-D` counts only before `-jar`, `-cp` and its argument are skipped; `--k=v` still counts anywhere |
| 3 | major | Dockerfile ENTRYPOINT and CMD never read, with no notice | Fixed: the effective command follows Kubernetes rules (command, args, image ENTRYPOINT, CMD), image words are `inferred`; no ENTRYPOINT gives a coverage notice |
| 4 | major | Only the uniform environment name was tried | Fixed: the legacy name (dashes to `_`) is tried second, in lookups, placeholders and exposure |
| 5 | major | Booleans accepted only true and false | Fixed: true/on/yes/1 and false/off/no/0 |
| 6 | minor | Empty value for an int, boolean or list key treated as a value | Fixed: treated as unset |
| 7 | minor | Probe groups default on for Kubernetes only, not Cloud Foundry | Open; documented below |
| 8 | minor | Duplicate YAML keys last-wins; explicit tags ignored; `1e3` floats stay strings | Open; documented below |
| 9 | minor | `read_only` access spelling gives unresolved | Open; conservative, documented below |

The independent oracle was updated to the same rules from Spring's behaviour, not from the resolver, and each fix has a regression test that runs the oracle. Not checked by the reviewer: the defaults table anchors, `spring.config.import` and `spring.config.location`, `spring.profiles.default`, app-type base paths (`spring.webflux.base-path`, `spring.mvc.servlet.path`), the safe YAML composer, and the tests. A second review round is not done.

Additional known limits from the review: probe groups are not enabled by default on Cloud Foundry (3.4 and later); duplicate YAML keys are not rejected; YAML explicit tags and exponent floats without a dot are typed as strings; `read_only` spellings give an unresolved access; a main class named instead of `-jar` is not detected, so `-D` after it is read as a JVM option; `spring.profiles.default` is not read.

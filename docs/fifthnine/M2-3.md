## What was delivered

`resolve/python_app.py` reads Python sources with `ast`. Repository code is never imported or executed. A source root is a
directory with a Python build file (`pyproject.toml`, `requirements*.txt`) that detection found; its modules are parsed on demand,
and the scans over every module test the raw text for a keyword first, so large repositories are not held in memory as trees.

| Fact | Subject | From |
|---|---|---|
| `stack.version` | `component:<fastapi, uvicorn, gunicorn, httpx, tenacity, python>[@root]` | M1 detections; `python` from the Dockerfile `FROM`, never `requires-python` (CA-N02) |
| `python.asgi_app` | `python:<module>:<attr>` | the `module:attr` the effective gunicorn or uvicorn command loads, resolved to a top-level `attr = FastAPI(...)` |
| `fastapi.debug` | app | `FastAPI(debug=...)` literal, a later `app.debug = ...`, or the cited default |
| `fastapi.route` | `app#METHOD:/full/path` | `@app.<method>`, `@router.<method>`, `api_route(methods=...)`, `include_router(prefix=...)`, `APIRouter(prefix=...)`, nested routers |
| `fastapi.route_table` | app | `{complete, routes}`; `complete` is false for dynamic registration (loops, conditions, functions), `mount()`, `add_api_route`, `root_path`, `routes=`, non-literal paths or prefixes, routers the scanner cannot follow |
| `gunicorn.setting` | `<container>#<bind, workers, worker_class, timeout, graceful_timeout>` | command-line flags (long, short, attached `-w4`), else the cited default with exposure through `GUNICORN_CMD_ARGS`, and through `PORT` (bind) and `WEB_CONCURRENCY` (workers), whose presence changes gunicorn's default |
| `uvicorn.setting` | `<container>#<host, port, timeout_graceful_shutdown, reload>` | command-line flags, then `UVICORN_*` variables (click `auto_envvar_prefix`), then the cited default |
| `python.settings_field` | `python:<module>.<Class>#<field>` | pydantic-settings fields: default, env name (`env_prefix`, `alias`, `validation_alias`), required fields, exposure from the container's env sources; an `env_file`, `secrets_dir` or `case_sensitive` setting is reported |
| `python.retry.stop`, `python.retry.wait` | `python:<module>.<function>` | tenacity `@retry` arguments (`stop_after_attempt`, `stop_after_delay`, `stop_never`, `|` and `&`; `wait_fixed`, `wait_random`, `wait_exponential` and variants, `+`), or the cited default |
| `python.http_client.timeout` | `python:<module>.<client>` | httpx `Client` and `AsyncClient` timeouts (number, `None`, tuple, `httpx.Timeout(...)`), only for clients a retried function calls (M0-D4; CA-N05) |
| `python.retry.client` | retried function | which client the retried function calls |
| `python.deadline` | route handler | `asyncio.timeout(...)` or `anyio.fail_after(...)` in a route handler; a value read from a settings field inherits its exposure |
| `python.call_reaches` | route handler | a retried function the handler calls, and whether the call is inside the deadline |

The effective command is the Kubernetes `command` and `args`, or the image `ENTRYPOINT` and `CMD` of the linked Dockerfile
(inferred). A shell command is expanded with the same POSIX subset M2-2 uses (`resolve/shellcmd.py`); anything outside it leaves
the server settings unread, with a coverage notice. `python -m gunicorn` and `python -m uvicorn` are recognised.

**Defaults table** `data/defaults/python.v1.yaml`. Each default was read with `ast` from the tagged upstream source at every release
tag in the supported range in `support_matrix.v1.yaml` (fastapi 0.100.0 and later: 186 tags; tenacity 8.x and 9.x: 20; httpx 0.27 and
0.28: 5; gunicorn 21 to 26: 21; uvicorn 0.30 and later: 43). A default applies only to a detected version listed in its `verified_at`;
any other version gives an unresolved fact, never the nearest version's default. The cited line is the declaration at the release
the samples use. The answer key's two Python default citations (CA-P02, CA-T03) gained these `verified_at` lists; no value changed.

**Runtime comparison.** For each case the scan runs offline. A probe then loads the same repository with the real libraries
(FastAPI 0.159.1, pydantic-settings 2.11.0, tenacity 9.2.1, httpx 0.28.1, gunicorn 26.2.0, uvicorn 0.54.0) and reports what they
resolved: whether the application's router matches each scanned route (Starlette's own matching, no handler runs), the OpenAPI
operation count, `app.debug`, each settings field's default and whether the scanned env name binds it, each retried function's
stop and wait objects, each client's timeout, `gunicorn --print-config` for the effective arguments, and uvicorn's click parse of
its arguments and environment. The container command is run through a real shell with stand-in `gunicorn`, `uvicorn` and `python`
executables, so shell expansion is the shell's, not the scanner's. Facts the libraries cannot show (deadlines, call chains, which
client a function calls) are counted as not compared.

## Known limits

- Only facts tied to a container are produced when the container is linked to the source root. On the corpus no FastAPI container
  link was proposed (image names and build identities differ), so no application, route or server-setting facts appear there.
  Declared links arrive in M2-5.
- gunicorn configuration files are not read: with `-c`/`--config` (any form) or a `gunicorn.conf.py` anywhere in the source root,
  settings not given on the command line or in `GUNICORN_CMD_ARGS` are unresolved. `GUNICORN_CMD_ARGS` from the Deployment or the
  image `ENV` is parsed and applied below the command line.
- Command lines are parsed with option tables generated from gunicorn 26.2.0 and uvicorn 0.54.0 (`data/python_cli.v1.yaml`). An
  option outside the table makes the command opaque; options added or removed in other releases are not tracked.
- The module path assumes the source root is the import root. `--chdir`, `--pythonpath` and `--app-dir` make the application
  unresolved; other WORKDIR and COPY layouts are not checked.
- Late route registration (a route or router added after `include_router`) marks the table incomplete for FastAPI before 0.137 when
  it happens in the same module; across modules it is not detected. Built-in documentation routes are not listed.
- Routes come from module-level literal registration. Route handlers and deadlines are read one call deep; call chains through
  helpers are not followed.
- Settings values computed at import time, `default_factory`, nested settings models, `AliasChoices` and `env_nested_delimiter`
  are not modelled; affected fields are unresolved.
- Version ranges in build files (`~=`, `>=,<`) give unresolved versions and therefore unresolved defaults. The three M2-0 notes for
  M2-3 are not done: the `requirements/*.txt` layout of FA-06, classifying compatible-release ranges against the support range,
  and reporting a lockfile that contradicts its manifest (FA-04).
- The semantic oracle (`tests/support/`) does not cover Python facts. The runtime comparison is the check for them, on 15 cases.

against the real libraries (and FastAPI 0.115.0 for row 14) and reported 24 silent wrong values and 5 minor items on d815934.

| Finding | Disposition |
|---|---|
